# Architecture

This page describes the Pue JS runtime from the moment a scroll event is observed to the moment an emission reaches the audio output. Understanding the pipeline is not required to use the library, but it will help you make informed tuning decisions.

```ts
// The emission pipeline, conceptually
scroll → sample → kinematics → tonnage → odor → reverb → destination
```

## Emitters

An **emitter** is the unit of composition in Pue JS. It owns:

- a binding to one scroll container (`window` or an `Element`),
- an `AudioContext`, either private or shared through the `audioContext` option,
- a resolved acoustic profile,
- a lifecycle state.

Multiple emitters can coexist on a page — for instance, one per scrollable panel. When they share an `AudioContext`, their output is mixed by the browser at no additional cost.

### Lifecycle

| State       | Meaning                                                                        |
| ----------- | ------------------------------------------------------------------------------ |
| `idle`      | Created, not observing. No audio resources are allocated.                      |
| `suspended` | Observing, but the `AudioContext` is waiting for a user gesture.               |
| `running`   | Observing and emitting.                                                        |
| `destroyed` | All listeners and audio nodes released. Any further call throws `E_DESTROYED`. |

Transitions are reported through the `statechange` event.

## Scroll sampling

Pue JS never performs work inside the scroll event itself. A passive listener flags the container as dirty; the actual position is read once per animation frame. This guarantees that sampling cannot delay a frame and never forces a synchronous layout.

### Velocity

Instantaneous velocity is expressed in **pixels per second** and smoothed with a critically damped low-pass filter to remove trackpad jitter. Scrolls below the `threshold` (80 px/s by default) are considered incidental and produce no emission.

### Throttling

The `throttle` option controls how frequently emissions may be triggered:

| Strategy     | Behaviour                                                                     |
| ------------ | ----------------------------------------------------------------------------- |
| `"velocity"` | The minimum interval shortens as velocity increases. Default and recommended. |
| `"distance"` | One emission every `viewport height × 0.5` scrolled.                          |
| `number`     | A fixed minimum interval, in milliseconds.                                    |

## Tonnage

**Tonnage** is the perceived intensity of an emission, normalized between `0` and `1`. It is derived from velocity through a **tonnage curve** and drives gain, spectral brightness and, to a lesser extent, duration.

Three built-in curves are provided — `"linear"`, `"logarithmic"` (default) and `"exponential"`. The logarithmic curve matches the human perception of loudness and keeps slow reading discreet while preserving headroom for aggressive flicks.

Custom curves are plain functions:

```ts
import { createEmitter, defineTonnageCurve } from "puejs";

// Silent below 200 px/s, saturates at 3000 px/s
const gated = defineTonnageCurve((velocity) => {
  if (velocity < 200) return 0;
  return Math.min(1, (velocity - 200) / 2800);
});

createEmitter(window, { tonnage: gated });
```

## Acoustic profiles

An **acoustic profile** is the full set of parameters that shape an emission: pitch range, resonance, duration, odor selection and tonnage curve. The `presets` export provides four calibrated profiles:

| Preset             | Character                                                  |
| ------------------ | ---------------------------------------------------------- |
| `presets.organic`  | Balanced, warm, moderate resonance. The default.           |
| `presets.crisp`    | Short, bright transients for dense, content-heavy layouts. |
| `presets.deep`     | Low pitch, long decay. Suited to immersive storytelling.   |
| `presets.discreet` | Reduced gain and duration for productivity interfaces.     |

Options passed alongside `preset` are merged over it, so a preset can be refined without being redefined.

## Odors

**Odors** are the synthesis modules that generate the raw emission. Each odor lives in its own ES module under `puejs/odors`, which allows bundlers to eliminate those you do not import.

```ts
import { createEmitter } from "puejs";
import { staccato, sustained } from "puejs/odors";

createEmitter(window, { odors: [staccato, sustained] });
```

When several odors are provided, the runtime selects one per emission based on tonnage: short, light odors for low tonnage, sustained ones for high tonnage.

| Odor         | Size (gzip) | Profile                                       |
| ------------ | ----------- | --------------------------------------------- |
| `staccato`   | 0.3 kB      | Short, percussive. Low tonnage.               |
| `sustained`  | 0.4 kB      | Long, stable body. Medium to high tonnage.    |
| `tremolo`    | 0.5 kB      | Amplitude-modulated. Expressive.              |
| `infrasonic` | 0.9 kB      | Sub-bass emphasis. Requires capable hardware. |

Custom odors can be authored with [`defineOdor`](/docs/api#defineodor).

## Reverberation

Emissions are spatialized with a `ConvolverNode` loaded with the impulse response of a simulated room. Impulse responses are fetched lazily on first use and cached by the browser.

| Room          | RT60  | Use case                               |
| ------------- | ----- | -------------------------------------- |
| `"anechoic"`  | 0.0 s | Dry signal, no spatialization.         |
| `"studio"`    | 0.4 s | Subtle presence. Recommended for apps. |
| `"atrium"`    | 1.6 s | Open, airy.                            |
| `"cathedral"` | 4.8 s | Maximum grandeur.                      |

The `decay` option scales the impulse response tail, and `mix` controls the wet/dry ratio. Set `reverb: false` to bypass the convolver entirely.

## Latency budget

Pue JS targets a **2 ms** budget between the animation frame that detects qualifying motion and the moment the emission is scheduled on the audio thread. In practice, the median is 0.9 ms and the 99th percentile 1.8 ms on mid-range hardware.

This is achieved by:

- keeping synthesis inside a pre-warmed `AudioWorklet`,
- communicating with the worklet through a lock-free ring buffer backed by a `SharedArrayBuffer` when cross-origin isolation is available, and through `MessagePort` otherwise,
- scheduling emissions slightly ahead of `AudioContext.currentTime` to absorb jitter.

Each `emit` event exposes the measured `latency`, so you can verify the budget in your own telemetry.
